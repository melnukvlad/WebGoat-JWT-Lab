
# Дослідження вразливостей JWT у OWASP WebGoat

## 1. Мета роботи

Метою роботи є дослідження механізмів автентифікації та авторизації з використанням JSON Web Token (JWT), вивчення типових вразливостей JWT та способів їх запобігання.

Практична частина виконується у спеціалізованому навчальному вебзастосунку OWASP WebGoat, розгорнутому в Docker-контейнері на віртуальній машині Kali Linux.

## 2. Використане програмне забезпечення

Для виконання роботи використовувалося:

- Windows 11 — основна операційна система.
- Oracle VirtualBox — платформа віртуалізації.
- Kali Linux 2026.3 (64-bit) — гостьова операційна система.
- Docker — платформа контейнеризації.
- OWASP WebGoat — навчальний вебзастосунок для дослідження вразливостей.
- Mozilla Firefox — браузер для роботи з WebGoat.
- GitHub — платформа для зберігання звіту.

## 3. Підготовка середовища

### 3.1. Розгортання Kali Linux

Для створення ізольованого навчального середовища було встановлено Oracle VirtualBox.

З офіційного вебсайту Kali Linux завантажено готовий образ віртуальної машини для VirtualBox.

Після розпакування архіву файл конфігурації `.vbox` було відкрито у VirtualBox.

Основні параметри віртуальної машини:

- Операційна система: Kali Linux 2026.3.
- Оперативна пам'ять: 2048 МБ.
- Кількість процесорів: 2.
- Віртуальний диск: 80 ГБ.
- Мережевий адаптер: NAT.

Після запуску віртуальної машини було виконано авторизацію та перевірено доступ до мережі Інтернет.

### 3.2. Встановлення Docker

Для оновлення списку пакетів використано команду:

```bash
sudo apt update
```

Встановлення Docker:

```bash
sudo apt install -y docker.io
```

Для запуску Docker та налаштування автоматичного старту виконано:

```bash
sudo systemctl enable --now docker
```

Стан служби перевірено командою:

```bash
sudo systemctl status docker
```

Отриманий результат:

`Active: active (running)`

Це підтверджує успішний запуск служби Docker.

### 3.3. Розгортання OWASP WebGoat

Для розгортання навчального вебзастосунку використано офіційний Docker-образ `webgoat/webgoat`.

Контейнер створено та запущено командою:

```bash
sudo docker run -d --name webgoat -p 127.0.0.1:8080:8080 -p 127.0.0.1:9090:9090 -e TZ=Europe/Kyiv webgoat/webgoat
```

Використані параметри:

- `-d` — запуск контейнера у фоновому режимі.
- `--name webgoat` — назва контейнера.
- `-p` — прив'язка портів до локального інтерфейсу.
- `-e TZ=Europe/Kyiv` — налаштування часового поясу.
- `webgoat/webgoat` — образ навчального застосунку.

Перевірка запущеного контейнера:

```bash
sudo docker ps
```

Перегляд журналу роботи:

```bash
sudo docker logs --tail 30 webgoat
```

У журналі зафіксовано успішну ініціалізацію застосунку та створення стандартного користувача.

## 4. Теоретичні відомості про JWT

JSON Web Token (JWT) — це компактний формат представлення набору тверджень (claims), який часто використовується для передачі інформації про автентифікованого користувача між клієнтом і сервером.

Типовий підписаний JWT складається з трьох частин:

1. **Header** — заголовок із відомостями про тип токена та алгоритм підпису.
2. **Payload** — набір тверджень, наприклад ідентифікатор користувача, роль і термін дії токена.
3. **Signature** — криптографічний підпис, який дозволяє перевірити цілісність токена.

Структура:

`Header.Payload.Signature`

Частини JWT кодуються за допомогою Base64URL. При цьому вміст звичайного підписаного JWT не шифрується, тому конфіденційні дані не слід розміщувати у відкритому Payload.

Безпека використання JWT залежить від правильної перевірки підпису, дозволених алгоритмів, терміну дії токена та прав доступу користувача.
